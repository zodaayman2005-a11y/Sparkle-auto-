# HDI — Web Visual Art Director
Source: the supplied consolidated v1.0.1 skill; workflow preserved in references.
This entry point is a packaging adapter, not a replacement image tool.

Read `references/00-core.md` for the workflow, then load only the needed module:
01-capabilities.md; 02-art-direction.md; 03-asset-planning.md; 04-generation.md;
05-web-integration.md; 06-quality.md; 07-templates.md; 08-evals.md; 09-sources.md.
All are under this skill's references directory.

For Sparkle, combine this skill with `sparkle-auto-brand-overlay` and the current
`docs/sparkle-skills/PROJECT-CONTRACT.md`. The current landing-plan proposes props-only
art; the source character examples are not mandatory scene requirements.

Own one production loop: message → visual verb → inventory → brief → calibration
→ actual tool output → real layout integration → inspection → targeted revision.
Distinguish CODE / REAL / GENERATE / REUSE / OMIT. Keep logo and product UI authentic.
Do not create a new production pipeline competing with asset-production-direction.
Native component geometry is CODE; semantic text and buttons never become raster art.

Install/plan requests do not authorize image generation. During a later authorized
build, inspect actual tool capabilities and permissions; produce a needed calibration
asset when the tool is available, instead of stopping at prompts alone. Do not ask
for inspiration pictures as a prerequisite. Editing requires a real existing image.
Tools, model names, alpha and returned files must be verified rather than invented.

Load the source QA gates. Inspect the actual returned asset and its desktop/mobile
composition, retain provenance and distinguish agent selection from user approval.
A package installation test cannot establish successful image generation.
